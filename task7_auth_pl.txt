Zadanie 7.1
Utwórz nową usługę, która będzie wywoływana authorization-servicena tym samym poziomie co usługi Product i Import, z własnym stosem AWS CDK. Struktura projektu back-end powinna wyglądać następująco:
   backend-repository
      product-service
      import-service
      authorization-service
Utwórz funkcję lambda wywoływaną basicAuthorizerw ramach usługi autoryzacji.
Ta lambda powinna mieć co najmniej jedną zmienną środowiskową z następującymi danymi uwierzytelniającymi:
  {yours_github_account_login}=TEST_PASSWORD
{yours_github_account_login}- nazwa Twojego konta GitHub. Loginem użytkownika testowego powinna być nazwa Twojego konta GitHub.
TEST_PASSWORD- ciąg hasła. Hasło dla użytkownika testowego musi brzmieć „TEST_PASSWORD”
przykład:johndoe=TEST_PASSWORD
Ta basicAuthorizerlambda powinna przyjąć token autoryzacji podstawowej , zdekodować go i sprawdzić, czy dane uwierzytelniające dostarczone przez token istnieją w zmiennej środowiskowej lambda.
Ta lambda powinna zwrócić status HTTP 403, jeśli dostęp dla tego użytkownika jest odmówiony (nieprawidłowy authorization_token) i status HTTP 401, jeśli nagłówek Authorization nie został podany.
W przypadku pomyślnych autoryzacji lambda powinna zwrócić politykę IAM, która umożliwia wywołanie żądanej metody Dokumentacja
UWAGA: Nie wysyłaj swoich danych uwierzytelniających do GitHuba. Użyj polecenia .envfile i dotenvpackage, aby dodać zmienne środowiskowe do lambdy. Dodaj polecenie .envfile to .gitignorefile.

  .env file example:
    vasiapupkin=TEST_PASSWORD

Zadanie 7.3
Żądanie z aplikacji klienckiej do /importścieżki Usługi Importu powinno zawierać nagłówek Basic Authorization :
  Authorization: Basic {authorization_token}
{authorization_token}jest zakodowany w formacie base64{yours_github_account_login}:TEST_PASSWORD
przykład:Authorization: Basic sGLzdRxvZmw0ZXs0UGFzcw==
Klient powinien uzyskać authorization_tokenwartość z pamięci lokalnej przeglądarki
  const authorization_token = localStorage.getItem('authorization_token')
